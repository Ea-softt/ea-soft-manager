# EA-Soft Paystack V2 + MikroTik Hotspot

## Architecture

Customer phone
    |
    v
MikroTik Hotspot login.html
    |
    | Paystack InlineJS V2
    v
Paystack
    |
    | successful reference
    v
EA-Soft backend (/api/payment-complete)
    |
    | verify reference with Paystack SECRET KEY
    v
MikroTik RouterOS API
    |
    | create Hotspot user
    v
Voucher username/password
    |
    v
MikroTik Hotspot login

## Important security rule

Do NOT put the Paystack SECRET KEY or MikroTik username/password in login.html.

Only the Paystack PUBLIC key belongs in login.html.

## Setup

The backend includes compatibility handling for RouterOS 7.18+ `!empty` API
replies. When updating an existing server, upload the latest `server.js` and
restart the backend process. `/api/health` reports the deployed version;
`classic-routeros-api-2026-09-18-empty-reply-fix` includes this fix. If deletion
still fails after updating, inspect backend logs for connection or permission
errors. Manager records are retained when router deletion fails.

1. Install Node.js 18+.
2. Run:

   npm install

3. Copy .env.example to .env.
4. Fill in the real Paystack secret key.
5. Configure `MIKROTIK_HOST` and `MIKROTIK_PORT=8728` for the VLAN 10
    management address.
6. Create a dedicated MikroTik API account for this backend.
7. Create the Hotspot profiles:
   - 3-HOURS
   - DAILY
   - 3-DAYS
   - 7-DAYS
   - 30-DAYS

8. Start:

   npm start

9. Put the HTTPS backend URL into login.html. You do not need to buy a domain;
    use the HTTPS URL generated by your hosting provider:

    var PAYSTACK_BACKEND_URL = 'https://your-app.provider.example/api';

10. Upload login.html and the normal MikroTik hotspot files to the router.

## No-admin-PC deployment

The administration PC is not required to stay on. The Node payment server must
run on an always-on HTTPS host such as a small VPS, Azure App Service, Render,
Railway, or another server. These services provide a URL automatically, so a
custom domain is not required. Set `PAYSTACK_BACKEND_URL` to that public HTTPS URL.

RouterOS alone cannot securely do all of this workflow because it cannot run the
Node Paystack webhook/verification service or an SMS provider. Do not put the
Paystack secret key in the router hotspot files or expose the MikroTik API
to the public internet. MikroTik remains responsible for the hotspot page,
profiles, and voucher accounts; the small backend only handles payment and SMS.

The supported production flow is:

```text
Customer -> MikroTik hotspot page -> HTTPS payment backend -> Paystack
                                      |
                                      +-> MikroTik API -> hotspot voucher
                                      +-> SMS provider -> customer
```

The backend host must be able to reach `192.168.10.1:8728`. If it is outside the
LAN, use a VPN or a secure tunnel between the backend and MikroTik. The PC can be
turned off after deployment.

## MikroTik walled garden for the payment server

The hotspot client must be allowed to reach the computer running the Node server
before login. If that computer is `192.168.10.50` and the server uses port `3000`,
add this RouterOS rule:

```routeros
/ip hotspot walled-garden ip add dst-address=192.168.10.50 protocol=tcp dst-port=3000 action=accept comment="EA-Soft payment server"
```

The Node server must be running on the same LAN address:

```powershell
node server.js
```

The URL in `login.html` must match it exactly:

```js
var PAYSTACK_BACKEND_URL = 'http://192.168.10.50:3000/api';
```

If the hotspot login page is loaded over HTTPS, the browser may block an HTTP
backend as mixed content. In that case, expose the payment server over HTTPS and
change the URL to its HTTPS address.

## MikroTik API

The backend uses the classic RouterOS API on TCP port `8728` through the VLAN 10
management address. RouterOS REST and `www-ssl` are not required for this
workflow.

The API host must be the router management address on VLAN 10, not the hotspot
client gateway on VLAN 20. The payment server must have a route to the
VLAN 10 address. VLAN 20 clients only need access to the payment backend; they
do not need direct access to the RouterOS API.

The API account must have `read`, `write`, and `api` policies.

The backend, not the customer's browser, talks to MikroTik.

Voucher data quotas are assigned from the package shown on `login.html`:

| Package | Data quota |
| --- | ---: |
| 3 Hours | 5 GB |
| Daily | 11 GB |
| 3 Days | 17 GB |
| 7 Days | 33 GB |
| 30 Days | 90 GB |

## Paystack

The frontend uses Paystack InlineJS V2.
The backend verifies the reference before creating the voucher.

For production, replace the test public key and secret key with live keys.
